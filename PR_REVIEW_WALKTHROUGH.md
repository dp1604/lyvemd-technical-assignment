# Attachment A: a walkthrough of the review

**I would request changes before merging this PR.** Several problems affect who can see a result, whether its clinical interpretation is correct, and whether access is recorded reliably.

This companion gives an example for each of the 24 blockers in the [detailed review](PR_REVIEW.md). All findings originated with AI assistance. The examples explain what the code permits; they are reasoning examples, not executed requests or observed patient incidents. The supplied listing was not fixed, compiled, built or run.

The locations below use the attachment's printed line numbers. Controller, Service, Resolver, Calculator, Normalizer, Mapper, Repository and Writer refer respectively to ResultController, ResultService, ReferenceRangeResolver, EgfrCalculator, UnitNormalizer, ResultMapper, ResultRepository and AccessLogWriter. The attachment says the unshown helpers are defect-free; this review respects that boundary.

| Finding and location | Example | Why it matters and what to change |
| --- | --- | --- |
| **B01 — Proxy filtering uses a fixed list of encounters.** Service 27–33,57–72,116–122. | A 16-year-old has a new MHEV visit. Its encounter ID is absent from the eight-item list, so a registered proxy passes this filter. | Confidential results can reach a family member. Check the actual class, age and current individual proxy entitlement on every read: withhold ABSL/SUBU/MHEV from proxies at 12+ and end proxy access at 18. The unseen Actor helper may handle some link eligibility; the hardcoded visibility list is still insufficient. |
| **B02 — Patient visibility does not check clinician release.** Controller 99–101; Service 74–109,125–149. | A patient opens a newly recorded result before a clinician has released it. The self-access path and retrieval query have no release check. | Unreviewed results, including critical ones, can appear too early. Hold them until an attributable release action and require the critical-value path where applicable. A lab's final status is not clinician release. Notification delivery does not need to be added to this partial PR. |
| **B03 — The total includes hidden results.** Controller 51–58; Service 80–98. | A proxy sees two rows, but the response says total three because countResults counts the whole record. | The response reveals that concealed content exists and gives the client an incorrect paging total. Build the page and its count from the same caller-visible collection and consistent snapshot. A hidden row should not change either result. |
| **B04 — The denial path looks up the patient's name.** Controller 104–108; Writer 44–45. | An unauthorized request puts the patient's display name into the exception reason and warning log. | The log already contains unnecessary identifying information; whether the response also exposes it depends on the error renderer. Return a generic unavailable response without fetching the name. Keep necessary access attribution in the controlled audit store and use safe diagnostic categories. |
| **B05 — A read can succeed without its audit.** Service 74/95/100/125; Controller 51–54; Writer 27–45. | The read finishes, then the asynchronous audit write fails. The writer catches the error and continues. | The patient can receive content without the required durable access event. Put authorization, reading and synchronous audit insertion in one transaction, and commit before returning content. If the audit cannot commit, withhold the response. A later background log is not enough. |
| **B06 — Denied reads never reach the audit writer.** Controller 67–75,99–108; Writer 49–52. | Authorization fails, or a proxy requests a concealed detail. The endpoint exits before any successful-read audit call. | Those attempts leave no required denied event. recordDenied exists but has no shown caller. Record a denied outcome before returning the generic error, and structure the transaction so the denial itself does not roll back that audit. |
| **B07 — Conversion depends on display text.** Normalizer 24–54,61–62; Mapper 34–50. | Creatinine is coded umol/L but displayed as µmol/L. The substring check misses it, while the mapper's eGFR path passes the feed value straight to the calculator. | The same number can be interpreted in the wrong unit. Match the UCUM system/code, normalize once before interpretation and reject unsupported units. The 88.4 conversion factor is correct. No normalise call appears in the listing; an earlier normalization guarantee needs evidence rather than assumption. |
| **B08 — The eGFR equation mixes versions and uses race.** Calculator 13–14,44–53,62–67. | Two records have the same creatinine, age and sex, but a legacy race extension activates the 1.159 multiplier for one. | The estimate changes for a reason excluded by the required equation. Use the published race-free 2021 formula and independent reference cases. The current code combines newer α values with older constants, so describing it simply as the 2009 equation would also be inaccurate. |
| **B09 — The output is not converted to seconds.** Calculator 20,44–55; Mapper 48–65. | A consumer interprets the calculated per-minute number as the per-second quantity suggested by EGFR_UNIT. There is no division by 60. | That interpretation creates a sixtyfold scale error. Convert explicitly and return the derived value with its unit, chosen code and provenance. The unit constant is unused, so the listing does not tell us what an external client actually displays. |
| **B10 — The calculator checks presence, not suitability.** Calculator 29–42,47–55; Mapper 48–50. | A 17-year-old or a zero creatinine value reaches the adult calculator. When inputs are missing, the DTO gets an unexplained null instead. | The result can be inapplicable, and an absent estimate has no useful explanation. Check adult eligibility, appropriate clinical context and suitable positive standardized creatinine. Return a clear cannot-compute reason when those conditions are not met. |
| **B11 — Historical results use today's demographics.** Resolver 64,75–99; Calculator 34–42. | Haemoglobin measured at 13 is reopened after the 14th birthday. Its range now follows the current age; an absent birth date becomes99. | A past result can change interpretation without the measurement changing. Resolve age and applicable clinical-sex context at measurement time and retain that provenance. Administrative gender alone does not establish historical clinical sex, and unknown context should not silently default to male. |
| **B12 — The age 14 switch is applied to every analyte.** Resolver 38–50,66–85. | A 15-year-old receives adult BP/BMI ranges, while a 10-year-old sodium result has no range. | Both disagree with the supplied table. Apply each row's own conditions: Hb changes at 14; BP/BMI begin at 18; the electrolyte, HbA1c and sex-specific creatinine rows have no supplied age cutoff. The interval numbers themselves are correct. |
| **B13 — No range is presented as NORMAL.** Mapper 37–46. | Height has no applicable reference interval, so the initial NORMAL flag is returned unchanged. | The response suggests a clinical comparison took place when none did. Return a separate no-applicable state and reason. NORMAL should follow a comparison with an applicable range, and the client must distinguish the states in words as well as colour. |
| **B14 — The mapper expects every result to be scalar.** Mapper 31–45,69–75; Service 135–145. | A BP Observation has systolic and diastolic components but no parent numeric value. The mapper dereferences a top-level Quantity. | The page can fail or miss a component abnormality. Handle components and absent values explicitly, range-check each component against its own code and project component trends. The parent should not acquire an invented scalar value. |
| **B15 — An amendment can delete its original.** Repository 57–66,79–82; Mapper 63–65. | A correction shares patient, code and effective time with the original. upsert deletes the old row, and the mapper always returns correctionOf=null. | The original and its correction relationship are lost. Append a new version with a validated predecessor link and keep both retrievable. The destructive upsert is not called by the shown GET methods; it is a persistence defect, not a read-side deletion. |
| **B16 — Dynamic search inserts values into SQL.** Repository 44–54. | A caller supplies an untrusted patient/code value or sort direction to search. String.format puts it directly into the SQL statement. | A reachable caller could alter the patient boundary or trigger expensive/erroring SQL. Bind values, allowlist sort direction and bound the limit. The shown controller does not call search, so its ignored sort parameter is not evidence of an exposed exploit. |
| **B17 — Requesting a page still loads all history.** Service 78–89,129–148; Repository 25–27. | A request for ten results loads and decodes the patient's entire record before filtering, sorting and paging it. | CPU and memory use grow with that history, potentially slowing other requests. Bound parameters and move suitable query work into indexed SQL or a reviewed projection while preserving derived-input rules. Measurement is needed to quantify the limit; the code already shows why the page size does not bound the work. |
| **B18 — The rounded result has the wrong Java type.** Calculator 27/55. | Optional.of(Math.round(egfr)) is returned from a method declared Optional<Double>. | round(double) returns long, which boxes as Long. That expression cannot satisfy the declared return type. Settle the numeric/display policy and ask the author to reconcile the supplied source with the successful-build report. |
| **B19 — The routes differ from the contract.** Controller 23,41/62/79. | A client requests /patients/..., while these methods are mapped under /api/v1/patients/.... | The documented client path needs a compatibility mapping that the listing does not provide. Expose the required routes or agree and verify a contract change. An unseen deployment rewrite should not be assumed. This partial PR need not implement every other Part 2 component. |
| **B20 — The gender enum uses the wrong type name.** Resolver 98–99; Calculator 39–40. | The source refers to org.hl7.fhir.r4.model.AdministrativeGender.FEMALE. | The R4 API uses Enumerations.AdministrativeGender. The top-level type reference is another build blocker, separate from whether administrative gender is a suitable clinical input. Check the exact dependency and artifact the author tested. |
| **B21 — Coding order determines the analyte.** Resolver 59; Mapper 31–32/49; Service 136. | A concept contains a local Hb code first and LOINC 718-7 second. Changing their order changes which code the mapper sees. | A range or trend can disappear; a local-code collision could trigger the wrong calculation. Select by system and code, independently of order, and reject ambiguity. FHIR gives coding order no meaning. No first-LOINC profile is established by the listing. |
| **B22 — A reference string is stored as the patient key.** Repository 63/73 versus 25–40. | Subject Patient/p1 is stored in patient_id, but a request for patient p1 searches using the bare key. | That observation can disappear from the patient's list, total or detail. Resolve and validate references to the canonical patient key before persistence, then use that representation consistently. This does not establish a separate defect in the unseen codec or migration. |
| **B23 — A qualified value becomes an exact one.** Mapper 34–35,53–65,73–74; Calculator 29–38. | If the input profile accepts creatinine <1 mg/dL, the mapper/calculator takes exact 1 and drops the comparator. | A measurement bound becomes a falsely precise value and derived estimate. Preserve its meaning or return unavailable/reject it before calculation. The mapping loses the qualifier; whether such input is admitted depends on the enforced profile, which the author needs to show. |
| **B24 — Equal-time results have no paging tie-breaker.** Service 78–88; Repository 24–27. | Two equal-time rows arrive as A,B on one fetch and B,A on another. With limit 1, the second page can repeat A and omit B. | Patients can see unstable or apparently missing results. Use a consistent effective-time-plus-ID order before paging and test equal-time boundaries. Supporting an optional user-selected sort is a separate, nonblocking product choice. |

## Where I would start

Ask the author to reconcile B18/B20 with the reported 14 passing tests: which commit, dependency versions, build command and results were used? A different artifact may explain the discrepancy.

Before merge, address the confidentiality, release and audit failures alongside the clinical identity, units, equation and history errors. Then verify stable, bounded reads. Request focused checks for each repaired boundary and a regression matrix; the reported 88% coverage and staging budget need their assertions and conditions to be meaningful.

Keep the smaller cleanup items separate: unused wiring and misleading comments, the advertised optional sort, and display precision. Timing equivalence and concurrent revocation need evidence and a clear snapshot boundary. An already-authorized response cannot simply be recalled after it has started.

## Questions to take back to the author

1. Which input/storage profile is enforced for coding systems, qualified quantities, effective times and normalized units? Where is that boundary verified?
2. Which statuses qualify for calculation and trends? How are withdrawn or entered-in-error results retained without presenting them as current measurements?
3. Is an outer write transaction responsible for upsert's delete/insert, and is rollback checked? A transaction could prevent partial replacement, but would not make deleting the original meet the history requirement.
4. Where do BMI/eGFR derived rows, reasons for noncomputation, versions and input provenance come from across list, detail and trend? This listing covers only part of the feature.
5. What are the agreed date/time, amendment-trend and revocation boundaries? DateUtil and AgeUtil remain defect-free; their callers still need a clear contract.

The task's potassium 2947-0 discrepancy stays in the specification caveats. Following the supplied table is not another junior defect.
