# Clinical read boundary — current detail checkpoint

The original Task46 requires both retained versions to be retrievable with `correctionOf`. Therefore the Task49 detail dependency was implemented before closing Group4. The results-list, trend and access-log routes, local clinician workflow and their complete cross-route regression remain Group5. This document describes current code, not completed Group5 or final security certification.

`GET /patients/{patientId}/results/{observationId}` uses the bounded untrusted-header parser, known test roster, stored patient/encounter/proxy relationships and one Repeatable Read action. Entitlement, visible content, interpretation, response materialization and categorical `RESULT_DETAIL` audit all occur before commit/HTTP delivery. Malformed actor declarations return400 without patient-existence reasons. Known-but-unavailable targets and unrelated/unknown/mismatched actors use the same safe404 outcome; failed audit/commit withholds content. No observation identifier, analyte, value or query details enter the categorical audit action/source or ordinary logs.

## Shared visibility predicate

- PATIENT must be that stored patient; CLINICIAN must be on one of their stored encounters. STAFF has no clinical access. The declared actor/role must match the synthetic roster first; this remains impersonatable test identity, not production authentication.
- PROXY needs an individual active link with no revocation timestamp. Request age uses UTC date and completed ISO calendar years; missing/future birth date denies, and access ends on the18th birthday. At12 and over, ABSL/SUBU/MHEV encounters and their observations are excluded regardless of their historical measurement date. A source observation without an encounter is not classified as one of those protected encounters. No source class or relationship is inferred from names/headers.
- Patient/proxy source records must be final/amended/corrected and have a completed clinician review and release with known criticality. CRITICAL requires critical-path attestation. A source-critical result cannot pass through an inconsistent NONCRITICAL review. A clinician may inspect held source records for their entitled patient; this is not a release action.
- SQL applies these predicates before clinical models are built. The memoized visible-series boundary then requires a complete visible correction ancestry. Missing/concealed ancestors and cycles fail closed. `correctionOf` and `correctedBy` derive only from that visible graph, never from a global successor-existence query. An original's response stays unchanged when its new successor is concealed; a released child cannot reveal a held ancestor. The visible successor map is computed once, avoiding a whole-series scan per rendered row.

The response includes ID, LOINC code, value, unit/unitCode, precise effective time, source status, range or null, textual flag/reason, nullable `correctionOf`, visible `correctedBy`, release state, reviewed criticality, original source-critical signal and BP components with their own ranges/flags. Null values are not converted to zero; unknown/no-applicable ranges are not called normal. Historical stored context feeds the clinical interpreter. Names, current administrative gender, birth dates, full input resources and internal validator messages are not returned.

## Non-disclosure, transaction and scaling limits

The detail SQL loads the same eligible patient view independently of the requested observation ID. Hidden and nonexistent IDs then follow the same ancestry, lookup, categorical denial audit and404 serialization path. Status/body equality and hidden-successor/ancestor cases are checked; the code does not promise physically identical wall-clock times under scheduler, cache, database-load or network variation. Wider route/paging/derived-output and statistical timing checks remain pending in Group5/final regression. No blanket timing-proof claim is made.

The shared assessment view materializes the eligible patient series with a patient-first index, then performs linear correction-ancestry processing and precomputes successor metadata. This also supplies later caller-visible derivations. It has a per-patient memory/CPU cost; a15-second transaction/10-second SQL timeout does not impose a hard limit on arbitrary Java computation or memory. Do not silently truncate history or ancestry to claim scale. Performance/query-plan work must measure the actual dataset, and the production note must distinguish this implementation from proposed incremental/paged materialization at larger per-patient histories. No9-million-row or90-million-row measurement is claimed.

A revocation committed before the action snapshot denies it; one committed after an already-authorized snapshot cannot retract an in-flight response. Total DB failure prevents auditing into that same DB; fail closed and emit only a constant operational warning. Migration/test-owner access is a trusted local administration boundary, not an alternative caller API. Test fixtures may set release states to exercise visibility, but those writes are not evidence that the pending clinician review/release commands or deterministic generator exist.
