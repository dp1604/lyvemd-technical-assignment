This inventory maps the application entry points to their authorization and audit boundaries. It supports review of this source; it does not establish controls over future routes, a compromised process or operators holding database credentials.

HTTP HEAD handling, where supplied by Spring for GET mappings, reaches the same GET controller/action; framework OPTIONS/error metadata does not select clinical rows. No source-mapped generic FHIR GET/search, repository/debug/admin mutation, release, proxy-provisioning, login, export or notification endpoint was found. POM contains Spring Web/JDBC and HAPI support, without an actuator or Spring Data REST dependency. This is a source/dependency observation, not a dynamically enumerated deployment inventory.

`ActorHeaders` requires one bounded ID and exact role, but headers remain impersonatable test declarations. `AuditedReadAction` checks stored roster before invoking read callbacks. `RequestTransaction` is REQUIRES_NEW, read-write Repeatable Read with a15-second transaction budget; results are materialized in its callback and exposed only after commit. Expected denials are returned outcomes so DENIED can commit; audit/commit failure withholds clinical content. `PrivacyHeaders` supplies no-store, no-cache, nosniff, frame denial, no-referrer and self-only CSP. `SafeExceptionHandler` and terminal ingestion/workflow catches log fixed categories without raw exceptions, SQL or clinical input.

Runtime and migration/administration database credentials are powerful trust boundaries. The runtime role can SELECT underlying clinical tables; this build enforces per-patient authorization in the application, not PostgreSQL row-level security. Someone possessing those credentials or trusted local administrator access can operate outside the HTTP identity gate. The local connection is loopback/SCRAM with ignored protected secrets; production credential/network/operator auditing and approved disclosure/key/recovery controls remain design duties. Do not tell an auditor that source mapping tests make direct privileged database access impossible.
