# Decision register

These are the assessment policies I reviewed and adopted. They resolve gaps or conflicts in the brief; they do not replace employer clarification or clinical approval. The original proposals and adoption records remain in authentic Git history at commit `356502c7`. The exact access-rule instruction is retained unchanged.

| Decision | Choice and reason |
|---|---|
| D-01 — Ingestion scope | Accept JSON R4 transaction Bundles containing POST creates of Patient, Encounter and Observation. Validate every entry and reject unsupported operations atomically. Resolve local UUID references without remote fetching. This is a bounded adapter, not a general FHIR server. |
| D-02 — Failure envelope | Follow the brief's failed transaction-response with indexed safe entry errors and no committed siblings. Disclose that normative R4 instead requires a single OperationOutcome for a failed transaction. Malformed transport input cannot always identify an entry. |
| D-03 — Replay and corrections | Require actor-scoped exact-body idempotency with durable completed outcomes and concurrency control. Corrections append a fresh linked source and retain the original. Restrict corrections to the current head and supported unchanged patient/analyte/encounter/effective context; reject branching, cycles and unsupported context changes. |
| D-04 — Actors and log access | Keep the required test headers, check actor/role declarations against the stored roster and enforce stored rights. Only known clinicians ingest. Access logs are available to the patient themself or STAFF. Test headers are impersonatable and provide no production identity assurance. |
| D-05 — Time, context and visible inputs | Use the current UTC date for proxy age and the observation's UTC date with explicit effective-dated clinical-sex context for clinical interpretation. Derive BMI only from caller-visible inputs at or before the anchor. Hidden inputs and hidden successors must not create an oracle. Do not invent freshness or critical thresholds. |
| D-06 — Release | Hold new results by default. Require an entitled clinician's review/classification and a separate attributable release. Critical results require workflow-completion attestation. Lab final status alone does not release a result, and this demonstration adds no notification transport. |
| D-07 — Read auditing | Treat the complete read action and audit insert as one fresh Repeatable Read transaction. Materialize permitted content and commit before sending it; commit expected denials as audit outcomes. Audit failure withholds content. An already authorized snapshot cannot be withdrawn retroactively, and an unavailable database cannot write to itself. |
| D-08 — Codes and units | Use BP panel 85354-9 and eGFR 98979-8. Normalize creatinine before calculation. Retain the task's eGFR display label while supplying valid machine UCUM `mL/s/{1.73_m2}`; do not parse its display notation as a UCUM decimal expression. |
| D-09 — Derived-only inputs | Reject incoming BMI/eGFR Observations with the entire Bundle. Atlas derives these from required inputs, avoiding an unsupported second authority. This is the assessment input profile, not a FHIR prohibition on upstream derived results. |
| D-10 — Leap-day age | Use completed ISO calendar years consistently: a person born on 29 February advances completed age on 1 March in a non-leap year. This is a declared assessment convention, not an assertion about jurisdictional legal age. |
| D-11 — Extension identifiers | Use locally defined HTTPS identifiers under `https://example.org/fhir/StructureDefinition/` for clinical-sex context and correction links, with no remote fetching. These are assessment identifiers, not a claimed production namespace; they supersede the original proposed URNs. |
| D-12 — Unavailable POST references | Return the same indexed HTTP 400 transaction-response REFERENCE_UNAVAILABLE error for missing and unauthorized stored patient references. This preserves the invalid-entry contract without disclosing patient existence. GET and unknown-actor behavior remains the declared safe 404. |
| D-13 — Clinical workflow | Use a one-way, audited local workflow: held results are reviewed/classified and then separately released by an entitled clinician. Critical completion is attested before release. Coordinate first release with corrections so a superseded held predecessor cannot newly release. An earlier valid release is retained. |
| D-14 — Individual proxy revocation | Allow a known patient acting as themself to revoke one existing individual proxy link. Preserve the first revoker/time and target-proxy audit attribution; repeated revocation is an audited no-op. Other links remain unchanged. No provisioning, reinstatement or STAFF revocation authority is introduced. |
| D-15 — History and trends | Retain original and corrected source rows with visible links. Result lists include retained visible history and calculated views; trends select eligible latest visible correction heads. Derived values use caller-visible inputs and inherit their release/visibility. Concealed ancestors or successors must not leak through values, timestamps, counts, provenance or links. |
| D-16 — Dataset size | Use 100 synthetic patients and about 10,000 source Observations, including all eight required scenarios and held/critical/revoked cases. This is large enough to exercise the assessment while remaining reproducible locally. It is separate from the nine-million-record production context. Exact final counts and measured performance are reported. |
| D-17 — Terminology conflict | Retain the supplied mapping of 2947-0 to potassium only for the synthetic assessment, prominently disclosed. Official LOINC defines 2947-0 as sodium in blood. Do not silently substitute 2823-3 or infer its specimen. Real feeds require verified specimen/terminology mapping and clinical-owner approval. |

## Sources and limits

The brief governs the house rules, required stack and clinical table. [FHIR R4 transaction responses](https://hl7.org/fhir/R4/http.html#transaction-response) explain D-02's deliberate deviation. [Patient.gender](https://hl7.org/fhir/R4/patient-definitions.html#Patient.gender) is administrative and is not automatically the historical clinical-sex input. The [NIDDK adult equation](https://www.niddk.nih.gov/research-funding/research-programs/kidney-clinical-research-epidemiology/laboratory/glomerular-filtration-rate-equations/adults), [LOINC 98979-8](https://loinc.org/98979-8), [UCUM](https://ucum.org/ucum) and [LOINC 2947-0](https://loinc.org/2947-0) support the calculation, units and disclosed terminology issue.

No real upstream samples, vendor deck, critical thresholds, complete historical-demographic feed or real authentication were supplied. Neither a Quantity nor a LOINC code proves standardized assay suitability. Actual source contracts, clinical freshness, legal jurisdiction, release authority and vendor capability need production validation. Critical attestation is not proof of real patient contact. A correction with a concealed ancestor remains withheld; a known-wrong original must never be released merely to expose a correction. Timing indistinguishability remains unestablished.
