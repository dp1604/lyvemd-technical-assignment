# Results list, secured detail and trend contract

All four GET routes use `AuditedReadAction`: parse untrusted test declarations, verify the synthetic actor/role pair, apply stored rights, materialize the response and write the categorical audit in one Repeatable Read transaction, then commit before HTTP. Expected denials persist; audit insertion or commit failure withholds content. Test declarations remain impersonatable, not production authentication. [Visibility](RESULT_VISIBILITY.md) defines release/proxy/correction filtering; [log entitlement](ACCESS_LOG.md) is separate.

## List and detail

`GET /patients/{id}/results?offset=&limit=` returns `items,total,offset,limit`. Offset defaults0 and accepts0–1,000,000; limit defaults50 and accepts1–200. Count and page use the same completed caller-visible collection: retained raw originals/corrections plus visible-input BMI/eGFR views, including explicit cannot-compute rows. SQL visibility and complete visible correction ancestry precede derivation, count and paging. Sort is exact effective descending, then ID ascending. A readable empty patient returns200 with empty items/total0. Offset beyond the collection returns empty items with its same visible total.

`GET /patients/{id}/results/{obsId}` resolves both assigned source UUIDs and virtual derived64hex IDs from that same authorized collection. It reads no observation by guessed ID before applying visibility. Hidden/absent IDs have the shared404 envelope. Source versions retain value/unit/range/flag, status, `correctionOf`, visible-only `correctedBy`, actual held/released state, reviewed criticality, source-critical signal and BP components. The raw list/detail history does not erase a correction's predecessor.

Derived rows explicitly carry `derived:true`, status `derived`, `computed`, nullable value/range, flag/reason, `cannotComputeReason`, selected source IDs/exact dates, method/version and notice. Their ID hashes length-prefixed UTF8 tokens for the ID-format version, method/version, analyte, anchor and sorted visible source IDs/times with SHA256. No hidden source, caller identity, global successor, total or database sequence contributes. Derived detail recomputes the current authorized view rather than treating that ID as authority.

`releaseState:INHERITED_FROM_VISIBLE_INPUTS` and per-source states describe inherited restrictions. Derived `criticality:null` deliberately makes no independent clinical classification; source-critical provenance is the OR of the selected visible inputs. These views are neither persisted source Observations nor independently reviewed/released records. A clinician's held inputs can produce a clinician-only view. Patient/proxy derivations use only their released, authorized inputs. No new critical threshold, clinical freshness interval, normal eGFR range or assay proof is invented.

## Trend

The exact task route is **singular**: `GET /patients/{id}/trend?code=&from=&to=`. Code must exactly match a supported analyte. The response is `code,points,total`, where total is the returned point count after authorization, visible-chain selection and time bounds. Points sort by exact effective ascending then ID ascending.

Raw trends use each chain's latest **visible** version. A concealed successor cannot suppress an original or appear in its metadata. A visible latest version with an ineligible source status is a null-value/range gap labelled `INPUT_STATUS_INELIGIBLE`, including null component values; an earlier source value is not revived. List/detail retain raw history. BMI/eGFR use the previously adopted latest eligible visible input heads and existing explicit missing-input rules. Computation uses the full authorized history before the display window, so a height before `from` can support a later weight. BP8480-6/8462-4 component trends inherit the authorized parent, project their own value/range/flag and retain the parent's detail ID as `parentObservationId`.

Bounds are inclusive. A date covers the whole UTC day, ending at23:59:59.999999999; an offset timestamp compares as an instant with nanosecond precision. Either omitted bound is open. Duplicate/unknown/empty parameters, unsupported codes, malformed numbers/dates, offset-free timestamps and reversed bounds receive an audited400 without echoing input. Parsing occurs inside the action after actor verification and before target entitlement; invalid queries for a known actor do not test whether a patient exists. Container-rejected malformed HTTP transport is a separate boundary and is not claimed to always create a database denial event.

## Verified limits

The final ReadApiIT coverage passed17 real HTTP/PostgreSQL cases plus3 query unit tests with zero failures/errors/skips. It covers hidden additions leaving list/trend body/count/derived IDs unchanged, concealed ancestry, corrections/gaps, prior-window BMI inputs, eGFR unavailable reasons, BP projection, exact nanosecond bounds, clinical roles/proxy birthdays and all protected classes, committed query denials, and insert/deferred-commit audit failure on every clinical GET. Owner-written review states in these tests are visibility fixtures, not proof that the actual local workflow or dataset loader ran.

The eligible patient history is materialized before interpretation/derivation/paging; this costs per-patient memory/CPU. Database timeouts do not hard-bound Java computation. Do not truncate history to manufacture performance. [Group5 evidence](evidence/group-5-reads-and-workflow.md) records actual timing, workflow/concurrency, full regression and CLI checks. [Group 6 actual dataset/scenario/recovery evidence](evidence/group-6-dataset.md) records the backend dataset checks; client, performance, clean-start and final regression/reconciliation remain separate gates. Equal public bodies/shared paths and finite measurements do not prove universal timing indistinguishability or production scale.
