# AI assistance logging protocol

This protocol applies to the entire task list through delivery. The assignment requires the actual request, returned material, shipped material and reasons for differences for each substantial AI-produced item. It separately requires R1-R6 delegation/retention reasons and the access-rule instruction verbatim.

## At each substantial increment

1. Add or update a stable item ID in AI_WORKING_LOG.md. Substantial items include requirements/architecture analysis, clinical research, code, tests, schema, scripts, dataset logic, review findings and document drafts. Group related revisions; keep material changes and rejected alternatives visible.
2. Record what was asked and its provenance. Prefer an actual retained instruction; label a summary, excerpt or redaction explicitly. Record the source message/artifact identifier. Never call reconstructed wording exact.
3. Describe what AI returned and identify the source output/code/document. Include meaningful AI-agent contributions. AI review is not human-origin discovery or candidate-run verification.
4. State what is retained, shipped, changed, deferred or rejected and why. Link the actual artifact or identify its commit/snapshot. A forecast, proposed policy, scaffold, local probe or unexecuted test is not completed product behavior.
5. Record checks, who performed them, results and limits. Do not infer candidate verification from a confirmation of a decision, or infer runtime behavior from static review/build success. Preserve failures and the change that addressed them.
6. Keep the log synchronized before each meaningful commit and again before final packaging. Routine formatting/tool retries can remain grouped under their substantial item.

## Exact access-rule instruction and delegation

Task 7 must record the candidate's actual R1-R6 delegation choices and reasons, and the access-rule implementation instruction with its exact wording, role, source and timing. The assignment's supplied rules and earlier AI-authored summaries remain part of provenance; do not retroactively invent a distinct user prompt from them. If an implementation instruction is amended, retain both actual versions and explain what shipped.

## Privacy and publication

Keep full retrieved chat, original correspondence, transcripts, workstation inventories, credentials and raw private logs in ignored local work. Commit curated disclosure, safe exact task instructions and source locators. Redaction must be disclosed; the access-rule instruction must be captured safely and exactly when issued, rather than altered without explanation. Preserve actual authorship and avoid backdating retrospective records.

## Final gate

Task 91 must account for each final substantial artifact and material change; verify the delegation decisions and exact access prompt; reconcile reviewer attribution and executed checks; and remove unsupported completeness, clinical, compliance or performance claims. Tasks 93-94 still inspect the actual package, history and reviewer access. A completed Task 6 establishes the working log, not a promise that future disclosure is already done.
