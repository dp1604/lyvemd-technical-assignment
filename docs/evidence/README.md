# Verification evidence

Store deliberately sanitized verification results here. Each meaningful result should identify what was checked, the command or reproducible procedure, dependency/configuration conditions, dataset size where relevant, observed result, and limitations.

Never add passwords, tokens, original patient records, source attachments, personal correspondence, local directory inventories or raw dumps. Raw local evidence belongs under ignored work/ until reviewed and reduced to suitable evidence. Do not label a planned check as a pass.

Environment setup is summarized in [environment.md](environment.md). Bounded actual results are recorded for [foundation](group-2-foundation.md), [clinical rules](group-3-clinical.md), [ingestion](group-4-ingestion.md), [reads/workflow](group-5-reads-and-workflow.md) and [dataset/scenarios/recovery](group-6-dataset.md). [Client](group-7-client.md), [regression](group-10-regression.md), [performance](../PERFORMANCE.md), [restore](group-12-restore.md) and [qualified clean-start](group-12-clean-start.md) results are recorded. [Current candidate contribution](../CANDIDATE_REVIEW.md) and [full reported responses](candidate-review-report.json) distinguish subsequent human review from those original executions. The [requirement-to-evidence matrix](../REQUIREMENT_MATRIX.md) identifies planned checks and current status; [Task 8 coverage evidence](task-8-matrix.md) is a documentation audit, not an application test result.

Historical evidence below retains its original date, scope, executor and result. A historical pending/no-human-check statement does not override the later candidate contribution record.
